## 実装で分けた境界

- **保存済み証明書と現在の入場判定は別。** 発行済み証明書・検証記録・COMMIT・操作記録を
  固定レビュー時点の全バイトで認証してから読む。メタデータの一致だけでは実行できない。
  将来の実操作では baseline 32 trace、過去の PUBLIC 2組それぞれ1,024 trace / 512 prefix 比較、
  元の102試行・64採用・38棄却の cohort、seal 全体、入力投影全体を再構成し、
  証明書全体との一致を確認する。
- **実行前後で必要な条件を分けた。** 実行前は未使用を確認し、消費後は自分が取得した正確な
  claim / fence / output との結び付きを確認する。過去の「未使用」を永久に使わず、
  旧コードの未使用検査を無効化するフラグも追加しない。
- **固定試行と候補ごとの消費を区別した。** PUBLIC の固定 fence を先に消費し、
  次に候補の claim を消費する。候補ダイジェストの変更で試行枠を再利用できない。
  元の study は従来の固定 claim / output をそのまま使う。
- **保存と配送の失敗を分けた。** fence、claim、matrix COMMIT、候補、summary の結果は別々に
  false / true / unknown を保持する。既知の消費・確定を、後続の照合や stdout の失敗で取り消さない。
  自動再試行・再開・別名出力・部分出力の引き取りは追加しない。

PUBLIC と将来の sealed adapter は同じ生成・保存ループを通る。
ただし production CLI と本番候補作成コマンドはない。本番用 adapter の実動作も未確認。
詳細な条件、閉じた入力形式、失敗時の扱いは[実行方針](../strategy/countdown_feedback_budget_receiver_e4_execution.md)に固定した。

## レビューと回帰テスト

レビューは**同一担当による限定的なソース／境界レビュー**であり、独立した担当者や別実装による検証ではない。
次の5点を補強してから実装を固定した。

1. 実行入口では、明示された正確なダイジェストを必須にする。保存候補からの自動補完を認めない。
2. 保存層から消費成功が返った時点で消費済みを保持し、その後のリンク照合の失敗で unknown に戻さない。
3. 元の本番実行後に PUBLIC 証拠を読む場合も、元の候補レビュー時点に結び付けて認証する。
4. 固定パス・発行済み証明書のピン・関数の由来を検査し、実行時の差し替えを拒否する。
5. 静的検査と実操作のキャッシュ条件を分離する。静的検査はコンパイル後にも動作し、
   実際の受入検査は runtime 自身のキャッシュが残っていれば source / 証拠を読む前に拒否する。
