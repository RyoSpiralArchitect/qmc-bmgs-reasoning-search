# Feedback × budget: public qualification

This implements the public qualification gate of the
[v6 scientific design](strategy/countdown_thompson_feedback_budget_factorial_v6.md).
The fixed public problem is `(1,2,3,4,5,6) -> 720`. A standalone wrapper constructs
the new profiles and exercises the unchanged search package.

The [dated observation](observations/countdown_feedback_budget_v6_public_20260905.md)
and [tracked receipt](qualifications/countdown_feedback_budget_v6_public_20260905.json)
record the first qualification and independent verification.
After the full-PR review correction, a
[fresh qualification receipt](qualifications/countdown_feedback_budget_v6_public_revalidated_20260905.json)
records verification with the corrected executable bytes. Historical receipts
remain bound to their producing revisions.

## What is checked

The wrapper executes 16 new-profile traces (budgets 256/512, scales 0/16,
seeds 8192–8195) and eight legacy `score256` traces. It independently reconstructs
every run identity and performs the existing generative and byte-identical replay.
It also reproduces the eight frozen v5 binary/reciprocal anchor traces, including
their original IID/Sobol sources, seed, verifier budget, and expected digests.

Eight low/high pairs must have exactly the same accepted-event prefix. Only the
final `search_finished` event is removed; event indices, hash links, proposal and
random material, selection values, charges, verification, and backups all remain.
Eight legacy/new B256 pairs must have equal complete accepted-event histories.
This qualification's eight budget prefixes do not substitute for the future
development study's 96 prefix checks.

All 24 budgeted traces must stop solely on `legal_action_scores`, with zero
overshoot and positive secondary headroom. The attempted charge is independently
checked to exceed only the primary cap. Terminal counts are derived from events:
`T256 >= 1`, `T512 >= 3`, and `T512 >= T256 + 1`. The first added terminal must
complete the low run's unfinished or current-next trajectory. Exact success
cannot disappear and minimum terminal error cannot increase along that prefix.
These are integrity checks on this public fixture, not estimates of method quality.

## Frozen fixture identities

[The identity manifest](fixtures/countdown_feedback_budget_v6_public.json) records
the qualification problem plus twelve public full-shape fixture problems with
the same inputs and targets 1–12. The latter fix the future 192-cell fixture's
identities and factor order. That fixture is not executed by this wrapper.
Future cohort generation must exclude every listed task fingerprint and source
multiset fingerprint. The public problems intentionally share one source
multiset; they are not twelve independent development tasks.

## Reproduce and independently verify

Use the frozen CPython 3.13.13 arm64 CPU binary64 runtime with Torch 2.11.0. Each
process requires `-P -B`, this checkout's `src` on `PYTHONPATH`, and a fresh empty
mode-0700 `PYTHONPYCACHEPREFIX` directory outside the repository. Set the cache
variable to a new directory for verification as well. The source checkout must
be clean and contain the committed wrapper, design, and fixture manifest.

```sh
python3 -P -B scripts/qualify_feedback_budget.py --manifest
python3 -P -B scripts/qualify_feedback_budget.py --qualify artifacts/work/feedback-budget-public-v6
python3 -P -B scripts/qualify_feedback_budget.py --verify artifacts/work/feedback-budget-public-v6
```

The output must be a new direct child of the existing `artifacts/work` directory.
An existing output is refused. `records.jsonl` retains the 24 budgeted public
traces; `receipt.json` binds their exact bytes, source/runtime evidence, all
comparisons, and the eight anchor receipts. Anchor raw traces remain ephemeral
and are regenerated by verification. Failures after output creation retain
completed rows and `failure.json`; no PASS receipt is emitted.

Verification is a separate process that reads the stored records and reconstructs
the entire receipt. It checks every schedule/run identity before replay, repeats
all comparisons and anchor reproduction, and revalidates input/source snapshots.
It binds the producing revision and the same host/runtime. Documentation-only
descendant commits can verify old evidence when all protected code, design, and
fixture bytes remain unchanged. Cross-host reproducibility is not established.

Public evidence uses exclusive file creation in a new local directory. It does
not implement the transactional, durable, one-shot publication contract required
for the subsequent development runner. The explicit `development_execution_authorized`
field always remains false.
