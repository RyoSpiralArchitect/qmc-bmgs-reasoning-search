## Identity and authority boundaries

`--plan` is read-only and outcome-blind. It binds all source dependencies, loaded
module origins, runtime fingerprints, original design, exact method specs,
budget, ordered coordinates, source/seed exclusions and analysis rules. The
plan does not include its own file hash or candidate commit; the separate human
receipt binds its digest and the exact containing commit without a hash cycle.
All existing source files are included because the kernel intentionally depends
on private frozen-engine interfaces.

The authenticated original identity registry includes historical/canary/locked
identities; add the original64 and prior8/32/256 development cohorts. A
conservative static fixture superset adds every six-positive-integer1..10
literal tuple/list in tracked Python, with file/line and source hash. This
over-inclusive identity-only rule is not an assertion that static parsing can
discover arbitrary dynamically generated inputs. Registered historical seed
fields and explicitly declared regression roots are sealed too. Their source
files, identity counts and sorted sets appear in the executable plan.

Actual `--run` or `--analyze` requires all four arguments: plan digest, candidate
commit, human approval receipt, successful full-qualification process record.
The committed checkout must be clean and equal that exact commit. The human
record must state one run and one separate-process analysis, plus exclusions.
It is an auditable binding, not cryptographic proof of human consent: the
operator must verify the question and answer in the human conversation. Neither
the plan's literal digest argument nor an automation is execution authority.

Qualification must have exit0, successful postflight, no errors, identical
before/after preservation records, authenticated log/input/helper references,
and actual full-suite PASS/OK with no skips. No candidate-time pending record
is converted into a historical success. No record-only follow-up is described
as a second full-suite run.

## One-attempt publication and bounded analysis

The unique directory `artifacts/work/search-value-development-20261025-a` is the
run fence. Each evidence file is exclusive and fsynced; relative paths reject
symlink components. Source/code/runtime/plan changes fail preflight. During an
operation, the checkout is frozen and source/plan/exclusion bytes are checked
before cells and after processing. An external capture additionally preserves
all historical raw files, memberships and absent reserved slots.

The runner saves invalid guard-bound cells before stopping, so a negative or
invalid outcome is not erased. Partial generation or output never becomes a
complete COMMIT. Existing directories cannot be resumed or reused. COMMIT
requires every typed, ordered cell coordinate and exact file reference.

Analysis requires its own process and an unused `analysis.STARTED.json` fence.
It authenticates the complete COMMIT/membership and authority chain, regenerates
the cohort, then generatively replays **all1,408 cells** from empty state and
compares every byte. It independently reduces terminal flags and seven-axis
charge events. Shared random material is checked only at actual common keyed
coordinates between single16 and mean-off. This one-budget study has **zero
cross-budget prefix pairs**; earlier allocation prefix counts do not apply.

The analyzer retains at most two detailed cell records at the outer pair-cache
layer. Replay has its own temporary objects and all compact metrics remain;
this is not a total constant-memory or two-cell-RSS guarantee. Progress is
fsynced at completion, and each update is flushed. Elapsed time and native
process peak-RSS observations are resource diagnostics, not scientific work.
The plan rotates method groups by source and alternates the paired stochastic
method order; no runtime/energy/efficiency claim is made from this schedule.

## Complete readout, missingness and passive diagnostics

No source-level success readout is returned from an incomplete/duplicate/foreign
or invalid matrix: the caller retains the failure/partial evidence as
`INCOMPLETE_OR_INVALID`. On a complete matrix, exact rational mean/variance and
`mean +/- 2*source_sd/sqrt(n)` follow the original ordered gates: fewer than64
sources or zero variance gives null interval/UNRESOLVED; half-width>0.05 gives
IMPRECISE before any promising classification; lower>+0.02 is
PROMISING_FOR_FRESH_CONFIRMATION; upper<=+0.02 is
NO_PRACTICAL_UPLIFT_SIGNAL; otherwise UNRESOLVED. The diagnostic mean-off
interval is descriptive and has no promotion/readout gate.

Deterministic, solvability-filtered, non-replacement generation does not prove
independence/exchangeability or model interval coverage. This is not a2pp power
guarantee, equivalence, absence proof, population causality, superiority to all
baselines, or equal-total-compute evidence. Every status has null winner and
scientific_decision.

Retain all method/source/root actual and unspent work; exact successes and
losses; minimum error win/tie/loss/missing; source and root leave-one-out
sensitivity (not a confidence interval); every cell's first exact work or
no-hit censoring at stopping work; terminal/revisit counts. A missing terminal
means success false, error/first hit null. Proposal-internal counters are the
kernel's replay-authenticated reconstruction, not live instrumentation or new
charges; root action counts overlap the old proposal score axis.

Complete choices stay in the authenticated raw traces. Pair diagnostics retain
choice-sequence digests, common prefix, first differing selection and its
observed mean/prior/noise contributions. Toggling the mean on the same stored
history can identify a passive choice flip, not an alternative full rollout.
No diagnostic or secondary comparison can replace the sole scientific primary.
