# v7: sealed admission and one-shot replication connector

This connects the [fixed v7 contract](countdown_feedback_budget_replication_contract.md)
to source-disjoint cohort sealing, reviewed candidates, one-shot consumption,
1,024-cell execution, independent analysis and saved-summary verification. The
underlying search factors, frozen design, previous PUBLIC executable, v6 pipeline
and historical evidence are unchanged. CLI availability is not permission.

The new files are `feedback_budget_replication_admission.py`,
`feedback_budget_replication_execution_storage.py`,
`feedback_budget_replication_execution_analysis.py` and
`run_feedback_budget_replication_execution.py` under `scripts/`.
The pure mathematical reduction is identical to the qualified v7 PUBLIC
reduction except for its docstring and domain; an AST comparison tests this.
The connector independently admits inputs and replays/reduces new-domain
records. It does not relabel an old receipt or mutate old module globals.

## Sealing before outcome access

The sole generation slot is
`artifacts/work/feedback-budget-replication-cohort-v7`. Before invoking the new
recipe, the sealer independently analyzes the actual NEW connector PUBLIC
publication, requires the explicit expected summary digest and closes the
admission context. The preceding PUBLIC path, v6 connector and a standalone
preflight cannot satisfy this prerequisite.

The three-file transaction writes STARTED first, then the complete
preregistration, then SEALED last. Both the start marker and preregistration bind
the exact connector-qualification reference. The seal includes all 64 definitions,
generation rejection history, 1,024 task-keyed cells, 512 budget pairs and 256
four-arm blocks, but no solution witness, hardness profile or search outcome.

Independent loading checks complete no-follow/private/single-link file and
transaction closure before any regeneration. It validates the closed recipe,
both identity kinds, all exclusions, source/runtime and the exact new connector
qualification before reproducing the 64-task generator acceptance order. The
returned seal has detached immutable bytes and revalidates its file generation.

An occupied generation slot cannot be adopted, overwritten or resumed. Failures
retain STARTED/partial data and a failure marker where unambiguous. An uncertain
final seal gets no countermanding failure. Output-delivery failure after a
completed seal is `RESULT_DELIVERY_UNCERTAIN`, not invalid admission or permission
to generate again. The seal-only review candidate is a distinct
`/seal-review-candidate`, never a connector execution candidate.

## One-shot execution and independent analysis

The receiver-local private ledger is
`artifacts/work/feedback-budget-v7-authorization-ledger`. Replication consumption
is fixed per study, not per output, cohort hash or candidate file. Changing a
filename or reissuing a candidate cannot replenish it. PUBLIC claims use a
separate per-candidate namespace. The spent check precedes input regeneration,
PUBLIC requalification and search on repeat run requests.

After complete admission, a durable exclusive claim is written before output
creation or search. A resource preflight requires 1,152 descriptor slots before
baseline/admission work; it does not raise the host's limits. Publication then
writes STARTED, 1,024 ordered four-digit cell files, RECEIPT and COMMIT last:
1,027 files, bounded by 8 MiB per cell, 64 MiB per control/summary and 1 GiB total.

Every full cell identity, including the last, closes before the first generative
replay. All 1,024 traces, sole-primary-budget stopping and 512 complete accepted-
event budget-prefix/completion guarantees must pass before the ordered
mechanism, terminal-error and exact-success reductions. All losses, 64 task
rows, 16 patterns, 512 cross-scale pairs, 256 extensions and 64 leave-one-task-out
rows at denominator 252 remain reportable. Missing/invalid data is not zero.

Separate analysis revalidates the reviewed candidate, consumed claim, seal,
source/runtime and complete raw publication; it replays and recomputes the same
matrix. Saved-summary verification repeats this analysis and requires exact
canonical bytes. This is independent checking of one experiment, not another
sample. The finite-cohort screen maps only admitted replication data to
`SOURCE_DISJOINT_REPLICATION_SCREEN_PASS` or
`STOP_REPAIR_REPLICATION_SCREEN_NOT_MET`; PUBLIC scientific decisions remain
null. No population inference, causal claim, QMC superiority, additional trial
or locked-128 authority follows.

Failures distinguish `AUTHORIZATION_ALREADY_SPENT`, `CONSUMPTION_UNCERTAIN`,
`SPENT_NOT_RUN`, `INVALID_ANALYSIS`, `PUBLICATION_UNCERTAIN` and
`RESULT_DELIVERY_UNCERTAIN`. Preserve the claim and every partial/uncertain
artifact. Reanalyzing a structurally complete uncertain publication requires
an explicit operator disposition; never automatically chain after a nonzero
producer exit. No analysis or replacement summary restores the consumed claim.
These are local POSIX checks, not physical power-loss certification, a remote
authorization service or defense against an administrator deleting the ledger.

## Commands

Use absolute `src` on `PYTHONPATH`, `python3 -P -B` and a fresh empty owned
mode-0700 `PYTHONPYCACHEPREFIX` for each source-qualified process. Do not edit the
checkout during an operation. The two `--self-test` modes are nonauthorizing,
no-generation/no-search identity checks and work outside the checkout.

| Connector command | Required arguments |
| --- | --- |
| `--prepare-public` | `--output`, `--authorization` |
| `--prepare-replication` | `--output`, `--authorization`, `--qualification` |
| `--run-public` / `--run-replication` | `--authorization`, `--confirm-digest`, `--reviewed-revision` |
| `--analyze-public` / `--analyze-replication` | `--output`, `--summary` |
| `--verify-public` / `--verify-replication` | `--output`, `--summary` |

Use `scripts/run_feedback_budget_replication_execution.py` for that table.
Its `--manifest` describes only the fixed PUBLIC inputs. Prepare creates a local
candidate, not permission. Production candidate and qualification bytes must be
promoted unchanged into the reviewed Git tree before production execution.

The separate `scripts/feedback_budget_replication_admission.py` offers
`--seal-cohort --qualification FILE --expected-digest DIGEST`,
`--verify-seal DIRECTORY`, and `--candidate DIRECTORY --output PATH`, besides
`--self-test`. Generation is not an implicit part of prepare/run. Exact argument
sets are required; unknown or irrelevant options never become ignored overrides.
